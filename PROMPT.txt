PROJECT: NormalMe — a web app that answers "given who I am, 
how I feel right now, and what food I have, what should I cook?"

STACK
- Next.js 14+ (App Router, TypeScript, Tailwind)
- Supabase for Postgres DB, Auth (Google, Apple, email/password), and file storage
- Gemini API for dish recommendations and recipe generation (NO custom ML 
  model in v1 — recommendations are generated via a single structured LLM call, not 
  a trained recommender system)
- Hosted on Vercel + Supabase

CORE LOOP
1. User has a profile (skill level, diet type, allergens, cuisine prefs, household size, 
   equipment available).
2. User maintains a pantry: items with name, category (produce/protein/pantry/frozen), 
   quantity, and optional expiry date.
3. User picks a current energy level (Low / Normal / Full) which maps to effort/time 
   constraints for cooking.
4. Backend sends profile + pantry + energy + expiring items to Gemini API with a strict 
   JSON schema and gets back ranked dish suggestions with match reasoning.
5. Clicking a dish makes a second LLM call to generate the full recipe (ingredients, 
   steps, est. time) — also structured JSON.
6. Every recommendation shown and every user action (view/click/cook/skip/rate) is 
   logged to an `interactions` table, even though nothing uses it for ranking yet. 
   This is required from day one — it's the future training data.

HARD CONSTRAINTS
- Allergen and diet filtering is enforced in application code as a hard pre/post 
  filter around the LLM call — never rely on the LLM alone to respect allergens.
- All LLM calls must request structured JSON output and validate/parse it defensively 
  (LLMs can occasionally return malformed output — handle gracefully, don't crash).

DATA MODEL (initial tables)
- users, user_preferences (diet, allergens, skill, cuisines, equipment, household_size)
- pantry_items (user_id, name, category, quantity, unit, expiry_date)
- interactions (user_id, recipe_snapshot, action, context_snapshot [energy, expiring 
  items present], timestamp)
- shopping_list_items
- saved_recipes / ratings

BUILD ORDER (we are building feature-by-feature, in this sequence)
1. Auth (Supabase: Google, Apple, email/password)
2. Onboarding (skippable): skill level, allergens, diet type
3. Pantry input screen (manual entry first; barcode/OCR/voice later)
4. Notification of food expiry.
5. Home screen: energy selector + LLM-driven recommendations + "use soon" section
6. Recipe screen: LLM-generated recipe on dish click
7. Groceries/edit pantry screen
8. Shopping list
9. Insights (meals completed, waste reduced, money saved, energy trends)
10. Profile/account settings
